# Audio-to-Tongue-Articulation Models Beyond LAM Audio2Expression and NVIDIA Audio2Face-3D

## Are there published papers (ideally with public code/weights) on audio-to-tongue-shape prediction, articulatory inversion, or UTI-driven animation?

### Takeaway
Yes — there is a small but real research niche. The most usable hit is **"Speech Driven Tongue Animation" (Medina et al., CVPR 2022)**, which has a public GitHub repo, an MIT-licensed codebase, and a downloadable EMA-based dataset, though the released code itself is incomplete ("under construction"). Several other acoustic-to-articulatory-inversion (AAI) papers using ultrasound tongue imaging (UTI) or real-time MRI exist, but none of the others found have a confirmed public code release.

### Cited Findings
- **Speech Driven Tongue Animation (Medina et al., CVPR 2022)** — predicts tongue, jaw, and lip motion from speech audio alone, using self-supervised audio encoders (best-performing: Wav2Vec), trained on a large speech-to-tongue motion-capture dataset the authors collected. Output is **EMA 3D landmark sequences at 50 FPS** (not blendshapes). — [GitHub repo](https://github.com/salmedina/SpeechDrivenTongueAnimation); [Project page](https://salmedina.github.io/tongue-anim); [Paper PDF](https://salmedina.github.io/papers/Speech_Driven_Tongue_Animation__CVPR_2022.pdf); [CVF paper mirror](https://openaccess.thecvf.com/content/CVPR2022/papers/Medina_Speech_Driven_Tongue_Animation_CVPR_2022_paper.pdf)
- The repo's code is **MIT-licensed**, but its README marks the actual pipeline code ("Code" section) as **"UNDER CONSTRUCTION"** — setup/stage instructions exist (conda env `envs/tongueanim.yaml`, 5 pipeline stages: audio-feature extraction → dataset building → landmark-model training → eval → visualization) but the repo has only 54 stars / 10 forks / 3 open issues / 36 commits, suggesting limited completeness/activity. — [GitHub repo](https://github.com/salmedina/SpeechDrivenTongueAnimation)
- No official pretrained model weights are hosted by the authors; the pipeline requires downloading a third-party pretrained `wav2vec_large.pt` from Fairseq to bootstrap the audio encoder. — [GitHub repo](https://github.com/salmedina/SpeechDrivenTongueAnimation); [Fairseq wav2vec README](https://github.com/pytorch/fairseq/blob/main/examples/wav2vec/README.md)
- The companion **dataset is released** via Google Drive: mono 16kHz WAV audio, EMA 3D landmark sequences at 50 FPS, and transcripts. The data license requires citing the paper (citing the dataset URL alone is stated as insufficient). — [Dataset](https://drive.google.com/file/d/1AkbLsj41ftc56HNPWAI-Y26-QK4Bqbo9/view)
- **DNN-based Acoustic-to-Articulatory Inversion using Ultrasound Tongue Imaging** (Porras, Sepúlveda-Sepúlveda, Csapó, 2019) — fully-connected DNNs predict ultrasound tongue images directly from spectral acoustic features; compares an EigenTongue PCA-space target representation vs. raw ultrasound frames, finding CW-SSIM the most informative error metric. No code/weights release found in search. — [arXiv:1904.06083](https://arxiv.org/pdf/1904.06083)
- **Hu et al. 2022** — bidirectional LSTM acoustic-to-articulatory inversion trained on the 24-hour **TaL** audio+ultrasound corpus; used to improve ASR for elderly/dysarthric speech. The paper explicitly notes that **public ultrasound speech corpora are scarce and mostly English-only** — a structural bottleneck for this whole research area. No code release found in search. — [arXiv:2206.07327](https://arxiv.org/pdf/2206.07327.pdf)
- **"Complete reconstruction of the tongue contour through acoustic-to-articulatory inversion using real-time MRI data"** (2024) — AAI applied to real-time MRI tongue-contour data instead of ultrasound/EMA. No code link found. — [arXiv:2411.02037](https://arxiv.org/pdf/2411.02037)
- **AURORA: Model of Formant-to-Tongue Inversion for Didactic and Clinical Applications** (Strycharczuk & Kirkham, submitted Mar 2026, also at LREC 2026) — predicts 2D tongue displacement/shape from the first two formant values (F1/F2), explicitly positioned as a didactic/biofeedback tool. Trained on synchronized ultrasound + audio from 40 speakers; tongue contours auto-tracked with **DeepLabCut**, formants extracted with **FastTrack**. Released under **CC BY 4.0**. No GitHub/model-weights link surfaced in search, but the CC BY 4.0 license suggests openness is intended; worth checking the paper's appendix/supplementary links directly. — [arXiv:2603.17543](https://arxiv.org/pdf/2603.17543); [LREC 2026 paper](https://aclanthology.org/2026.lrec-1.441/)
- **Ultra2Speech** — deep learning framework for formant frequency estimation/tracking *from* ultrasound tongue images (the inverse direction: articulation→acoustics, not audio→tongue), relevant as adjacent UTI tooling but not an audio-to-tongue model itself. — [arXiv:2006.16367](https://arxiv.org/pdf/2006.16367)

### Inferences
- The field is small, academic, and largely code-incomplete: the one project with real audio→tongue output and a public dataset (Medina/CVPR 2022) outputs raw EMA landmark coordinates, not ready-to-use blendshapes or a rig-ready format — integrating it into a game-engine avatar pipeline would require building a landmark→blendshape/bone retargeting layer from scratch.
- Public ultrasound/EMA/MRI tongue corpora being scarce (explicitly flagged by Hu et al.) is likely why no major open "tongue model" has emerged the way ARKit-52 or Audio2Face did for jaw/lip — there isn't enough public tongue-tracked data to train one at production quality.
- The AURORA model (2026) is the most recent and most narrowly-scoped for exactly the "not just jaw/lip" ask, but it's a 2D formant→tongue didactic model, not a full 3D audio→blendshape production pipeline.

### Gaps
- Could not confirm whether Medina et al.'s "landmark prediction model" code (the actual trained-model inference step) was ever completed/released beyond the README's current "under construction" state — would need to open the repo's `src/` folder directly or check recent commits/issues.
- No code/weights found for the 2019 UTI-DNN paper, the 2022 Hu et al. LSTM-AAI paper, the 2024 RT-MRI paper, or confirmed for the 2026 AURORA paper — these are results of search-snippet-level investigation only, not an exhaustive check of each paper's own GitHub/supplementary links.

## Is there a blendshape/viseme standard beyond ARKit-52 with real tongue-position shapes and actual public audio-driven tooling behind it?

### Takeaway
Yes, in two credible-but-separate places: **NVIDIA Audio2Face-3D's own internal extended set** (52 ARKit + up to 16 additional tongue blendshapes, audio-driven) and **Reallusion iClone's extended iPhone-mocap set** (ARKit-52 + 11 tongue morphs, but camera-driven, not audio-driven). A third-party SDK (**mocap4face**) also claims tongue tracking but is proprietary-licensed and camera-driven, not audio-driven.

### Cited Findings
- **NVIDIA Audio2Face-3D microservice (v2.0)**: tongue blendshape output is **optional and configurable** via a deployment-time flag `enable_tongue_blendshapes` (default **false**) in the stylization config. When enabled, additional runtime controls `tongue_strength`, plus height/depth offsets, are exposed in per-character YAML configs (e.g. `config_james.yml`). — [NVIDIA ACE docs](https://docs.nvidia.com/ace/audio2face-3d-microservice/2.0/text/architecture/audio2face-ms.html) (via archive.docs.nvidia.com after redirect)
- Reported output size is inconsistent across sources: NVIDIA's own research paper describes the network as outputting an internal **10-dimensional tongue PCA vector**, which is inverse-transformed to full tongue pose and then solved into ARKit-style blendshape weights "for skin and tongue" — exact tongue blendshape count not stated in the excerpt read. A third-party developer forum post (unofficial, unverified) describes the API returning **55 total weights = ARKit-52 + 3 tongue shapes**; a separate NVIDIA docs page implies up to **68 = 52 face + 16 tongue**. These two secondary figures conflict and neither was confirmed against a primary schema file. — [arXiv:2508.16401](https://arxiv.org/html/2508.16401v1); forum post cited via search snippet, [docs.nvidia.com](https://docs.nvidia.com/ace/audio2face-3d-microservice/2.0/text/changelog.html)
- **Reallusion iClone's iPhone Face Mocap** adds **11 additional tongue animation morphs** on top of ARKit's standard set captured via the iPhone TrueDepth/ARKit camera — this is camera-driven (depth-camera mocap), not audio-driven, and is a proprietary Reallusion feature, not an open standard. — [Reallusion iPhone Face Mocap page](https://cdn-www.reallusion.com/iclone/motion-capture/iphone-live-face.html)
- **mocap4face SDK** (by Facemoji/alter) advertises **42 tracked facial expressions via blendshapes**, eye-gaze tracking, and **tongue tracking**, outputting ARKit-compatible blendshape weights, in a ~3MB on-device model. It is **not clearly open-source**: the npm package is governed by a proprietary "Facemoji SDK License Agreement," and the GitHub repo is **archived/read-only** (no longer maintained). — [npm package](https://npmjs.com/package/%400xalter%2Fmocap4face); [GitHub via aggregator](https://relatedrepos.com/gh/facemoji/mocap4face)
- **Phiz** (GitHub: SpookyCorgi/phiz) is a genuinely **GPLv3 open-source** ARKit-compatible blendshape tracker, but search results gave no indication it includes tongue tracking — it appears limited to the standard ARKit set. — [GitHub: phiz](https://www.github.com/SpookyCorgi/phiz)
- Standard **Apple ARKit-52** includes exactly one tongue-related shape, `tongueOut` (protrusion only, no position/shape detail) — confirmed by multiple independent sources describing the ARKit blendshape list. — [ARKit blendshapes guide](https://boggy-venom-2c5.notion.site/ARKIT-Expressions-335ef6b6bf7280bdaafff96d80c00daf)

### Inferences
- NVIDIA's extended internal tongue-blendshape set (whatever its true count — 3? 10? 16?) is the closest thing to an "extended ARKit-like standard with audio-driven tooling," but it's proprietary to NVIDIA's own pipeline/API, not an open/public standard other engines or tools can target independently — you'd be locked into the Audio2Face-3D service/SDK to get it.
- No evidence surfaced of an industry-wide or game-studio-published "extended FACS/blendshape standard" for tongue shapes that has independent public audio-driven tooling built against it (i.e., something analogous to how ARKit-52 has many independent audio-driven lip-sync tools). Every tongue-capable option found is either a single vendor's proprietary pipeline (NVIDIA, Reallusion, Facemoji) or purely camera/mocap-driven rather than audio-driven.

### Gaps
- Could not directly open NVIDIA's `configs/` folder contents (e.g. `config_james.yml`) in the Audio2Face-3D-Samples repo to resolve the conflicting 3-vs-10-vs-16 tongue-blendshape-count reports — GitHub's file browser wasn't expandable via the fetch tool used; a `git clone` and direct inspection of `configs/*.yml` and any `.proto`/schema files would resolve this definitively (see next section).
- Did not find any confirmation of an "extended FACS" or game-industry tongue-shape standard referenced on NVIDIA Omniverse forums as the task suggested checking — searches surfaced NVIDIA's own tongue params and Reallusion's, but no separate published cross-vendor standard.

## Does NVIDIA's Audio2Face-3D-Samples GitHub repo expose the raw tongue PCA output anywhere in its code/config, even if the standard CSV/ARKit export doesn't show it?

### Takeaway
Not confirmed either way from what was accessible. The repo (github.com/NVIDIA/Audio2Face-3D-Samples) does contain a `configs/` directory described as holding "static deployment, advanced and stylization configurations," which is the most likely place tongue-related keys (`enable_tongue_blendshapes`, `tongue_strength`, etc.) would live, but the page-fetch tool used could not expand/browse into that directory's file contents, so no direct quote of a tongue PCA value could be obtained. The research paper (same NVIDIA team, arXiv:2508.16401) confirms the model's *internal* representation is a 10-dimensional tongue PCA vector, but states the user-facing output is blendshape weights (post inverse-PCA transform) plus `tongue_strength`/height/depth post-processing controls — it does not state that raw PCA coefficients are ever exposed through the public SDK/API.

### Cited Findings
- Repo top-level structure confirmed as: `configs/`, `early_access/a2f-3d-authoring-sample-app`, `example_audio/`, `migration/deployment_configuration_files_from_v1.0_to_v1.2`, `proto/`, `quick-start/`, `scripts/`. The README describes `configs/` as containing "example static deployment, advanced and stylization configurations." — [GitHub: NVIDIA/Audio2Face-3D-Samples](https://github.com/NVIDIA/Audio2Face-3D-Samples)
- The research paper states the network's internal tongue representation is a **10-dimensional PCA vector**, computed via PCA over hand-animated tongue training data (animated by a professional animator from tracked jaw motion, since vision-based capture cannot see the tongue), then adapted per-actor via an affine transform. — [arXiv:2508.16401](https://arxiv.org/html/2508.16401v1)
- The paper states the network output is converted back to full tongue pose via **inverse PCA transform**, then solved into blendshape weights alongside skin blendshapes; user-facing controls described are the blendshape weights plus post-processing knobs (`tongue_strength`/height/depth), not raw PCA coefficients. — [arXiv:2508.16401](https://arxiv.org/html/2508.16401v1)
- The paper states the networks, SDK, and training framework are described as "open-weight and open-source" in the conclusion, but **no specific license name** (MIT/Apache/NVIDIA proprietary, etc.) was found in the portions read. — [arXiv:2508.16401](https://arxiv.org/html/2508.16401v1)
- A related NVIDIA Hugging Face dataset release, **Audio2Face-3D-Dataset-v1.0.0-claire**, exists and may contain additional training-level detail (potentially including tongue data/annotations), but its contents were not inspected in this research pass. — [HuggingFace: Nvidia/Audio2Face-3D-Dataset-v1.0.0-claire](https://huggingface.co/datasets/Nvidia/Audio2Face-3D-Dataset-v1.0.0-claire)

### Inferences
- Given the paper explicitly frames the 10-dim PCA vector as an *internal* representation that gets inverse-transformed before output, the most likely reality is that the public SDK/API does **not** expose raw tongue PCA coefficients — only final blendshape weights and the coarse `tongue_strength`/height/depth controls. But this is an inference from how the paper describes the pipeline, not a confirmed reading of the actual client/proto code.

### Gaps
- The `proto/` directory (likely gRPC/protobuf message definitions for the API) was not inspected — this is the single most likely place to definitively confirm or rule out a raw tongue-PCA field in the wire format, since protobuf schemas enumerate every field name. Recommend a direct `git clone https://github.com/NVIDIA/Audio2Face-3D-Samples` and `grep -ri tongue` across `proto/`, `configs/`, and `scripts/` to settle the exact tongue-blendshape count and confirm whether PCA coefficients are ever serialized — this research pass's web-fetch tool could not browse GitHub's directory tree deeply enough to do this remotely.
- The exact tongue blendshape count remains unresolved (conflicting secondary reports of 3, 10, or 16 — see previous section) and should be resolved from the same `proto/`/`configs/` inspection.

## Are there VTuber/VRChat community tools that track/drive tongue position from a phone's depth camera, hinting at a usable blendshape convention?

### Takeaway
Yes — tongue tracking exists in the VRChat/VTuber ecosystem via the **Meta Quest Pro's eye/face tracking** (routed into PC VRChat through the community **VRCFT (VRChat Face Tracking)** OSC bridge and the **ALXR** module) and via Blender-side conversion tools like **FaceKeys** that bake ARKit tongue shapes into VRChat's "Unified Expressions" convention. These are camera/sensor-driven, not audio-driven, but do show a real, currently-used tongue-blendshape naming convention (VRChat's Unified Expressions / OSCFT parameters) that could in principle be targeted by an audio-driven model.
 
### Cited Findings
- VRChat's own wiki states captured facial tracking data (from supported headsets/phones) is converted into blendshape values and sent into VRChat via **OSC**, typically through the community **VRCFT** bridge; the iPhone's Face ID (TrueDepth) sensor is listed among supported depth-camera sources. — [VRChat Wiki: Face Tracking](https://wiki.vrchat.com/wiki/Face_Tracking)
- **Meta Quest Pro tongue tracking** is reported to work in PC-VR VRChat through the **ALXR** module, but explicitly **does not work in the Quest standalone build of VRChat**; a 2024 commercial avatar add-on ("Soap Cats" FT DLC) also notes the Quest Pro tongue parameter not functioning in some configurations. — [Digital Trends coverage](https://digitaltrends.com/?p=3493678); [Soap Cats VRChat FT DLC](https://ironicsoap.gumroad.com/l/SoapCatsFT)
- **FaceKeys** (a commercial Blender add-on) explicitly bakes **ARKit mouth, jaw, and tongue shapes** into VRChat-ready viseme/shape keys and can output in the "**Unified Expressions**" naming convention used across the VRCFT ecosystem — evidence that a community-standardized tongue-shape-key naming convention exists and is actively used for avatar rigging, independent of how the tracking data itself is produced. — [FaceKeys product page](https://superhivemarket.com/products/facekeys?variant=25300)
- No evidence found of any **audio-driven** (as opposed to camera/depth-driven) tool in the VRChat/VTuber space that drives these tongue parameters from speech audio.

### Inferences
- The VRChat "Unified Expressions" / VRCFT tongue parameters are a genuine, currently-maintained, community-standard naming convention beyond bare ARKit-52 — if an audio-driven tongue model were to be built or adapted for a VRChat-style rig, targeting Unified Expressions' tongue parameters (rather than inventing a new tongue shape set) would maximize compatibility with existing avatars/tools. However, this is an inference, not a found connection — no existing audio-driven system targeting Unified Expressions tongue parameters was located.

### Gaps
- Could not find VRCFT's/Unified Expressions' own specification document directly (e.g., a canonical list of its tongue parameter names such as `TongueOut`, `TongueUp`, `TongueLeft`, etc., if they exist beyond simple protrusion) — would need to check the VRCFT GitHub repo's parameter schema directly for the exact tongue-shape vocabulary.
- No audio-driven tongue tool was found in this ecosystem at all — this key question is effectively answered "no" for the audio-driven angle; the value found is only in the blendshape-naming-convention angle.

## Is there TTS or articulatory-synthesis research jointly modeling tongue position (e.g., for medical/speech-therapy visualization) with public code?

### Takeaway
Several real-time tongue-visualization-for-speech-therapy systems exist and some are genuinely open-source (notably **ematoblender**, GPL-licensed), but all of the ones found are driven by **measured articulatory sensor data (EMA/ultrasound)**, not by a TTS or pure-audio model — i.e., they visualize tongue movement that was captured, not tongue movement predicted from arbitrary speech audio or text.

### Cited Findings
- **ematoblender** (Saarland University / DFKI, Steiner et al., Interspeech 2016) — a modular, **open-source, GPL-licensed** framework (hosted on GitHub) that streams or replays EMA (electromagnetic articulography) sensor data into **Blender**, using statistical shape models to render the tongue, lips, lower jaw, and palate in real time for speech-therapy/visual-feedback use. — [GitHub: m2ci-msp/ematoblender](https://github.com/m2ci-msp/ematoblender); [Interspeech 2016 paper](https://httpd.coli.uni-saarland.de/~steiner/publications/Interspeech2016.pdf); [arXiv:1612.06114](https://arxiv.org/pdf/1612.06114)
- **Opti-Speech** (Katz et al., UT Dallas Speech Production Lab, 2014) — a real-time 3D tongue/lip/jaw visual-feedback system from EMA data, commercially licensed via Vulintus for second-language training and speech-language pathology; **no public GitHub repo found**. — [UT Dallas Speech Production Lab](https://labs.utdallas.edu/speech-production-lab/research/optispeech)
- **Opti-Speech-VMT** (UT Dallas, Kumar et al. 2022 book chapter) — a research prototype built on the **open-source Unity engine** reporting ~17.4ms added latency for real-time visual-motor tracking experiments; described as a research prototype rather than a publicly released package. — [Kumar et al. 2022 chapter PDF](https://labs.utdallas.edu/speech-production-lab/files/2022/07/Kumar2022_Chapter_Opti-Speech-VMTImplementationA.pdf)
- **Ultrax** (CSTR, University of Edinburgh, Richmond & Renals, Interspeech 2012) — a project aiming to turn raw ultrasound tongue imaging into a simplified animated midsagittal vocal-tract display for speech therapy; the authors explicitly flag MRI as "a prime candidate source for extra anatomical data" for building better animatable vocal-tract models, implying their ultrasound-only approach has known anatomical gaps. Open-source status not confirmed. — [Ultrax paper (CSTR)](https://www.cstr.ed.ac.uk/downloads/publications/2012/RichmondRenalsIS2012.pdf)
- **VisArtico** — a separate EMA visualization tool supporting both Carstens and NDI electromagnetic articulograph hardware, displaying tongue/lips/jaw/palate; found via search only, open-source status not confirmed in this pass.

### Inferences
- None of the tools in this category are TTS systems or audio-driven in the sense the task asks about (predicting tongue shape from arbitrary input speech/text) — they are all playback/visualization layers for *measured* articulatory sensor streams (EMA or ultrasound), which is a materially different (and more mature/clinically-used) technology than an audio→tongue predictive model.
- The clearest path from this sub-area toward an actual audio-driven tongue model is combining the Medina et al. CVPR 2022 EMA-landmark-prediction approach (Key Question 1) with a visualization/rigging layer like ematoblender's Blender pipeline — but no existing project was found that already does this combination end-to-end.

### Gaps
- Could not confirm whether Opti-Speech, Opti-Speech-VMT, Ultrax, or VisArtico have any public source code release — none surfaced a GitHub/GitLab link in search results; would need direct contact with the respective labs (UT Dallas Speech Production Lab, CSTR Edinburgh) to confirm licensing/availability.
- Did not find any TTS research (text-to-speech systems, as opposed to sensor-driven visualizers) that jointly models articulatory tongue position end-to-end with public code — this specific combination (TTS + tongue articulation + public code) was not found anywhere in this research pass.

## Overall Summary for Report Writer

**Bottom line: nothing found rises to "real, usable, open-source, audio-driven tongue model with weights" at the level of polish of LAM Audio2Expression or NVIDIA Audio2Face-3D.** The single closest candidate — Medina et al.'s CVPR 2022 "Speech Driven Tongue Animation" (MIT-licensed GitHub repo, public EMA dataset) — has an incomplete/"under construction" code release and outputs raw EMA landmarks rather than blendshapes, so it would need substantial integration work (audio-feature pipeline is usable today; the trained inference model and landmark→blendshape conversion are not readily available). NVIDIA's Audio2Face-3D itself already goes further than publicly documented in the task's premise: it has an internal 10-dim tongue PCA representation and an optional, configurable tongue-blendshape output (`enable_tongue_blendshapes`), making it arguably the most complete audio-driven tongue solution that exists today, even though exact output details (3 vs 10 vs 16 tongue shapes) are unresolved from secondary sources and would require direct repo/proto inspection to confirm. Everything else found — UTI/AAI academic papers, VRChat/VTuber tongue tracking, speech-therapy EMA visualizers — is either code-unavailable, camera/sensor-driven rather than audio-driven, or a visualization layer rather than a predictive model.
